收尾

UI 设计规则

  • 主结构使用 NavigationSplitView
  • 专辑区使用 LazyVGrid
  • 曲目区优先使用原生 Table 或 List
  • 搜索使用 searchable 与系统工具栏
  • 按钮、菜单、进度、音量均使用系统控件
  • 不绘制自定义按钮、卡片材质和窗口装饰
  • 界面文案不使用句号
  • 不添加灰色二级描述，确有必要时先征得同意

如何参考 Amperfy

专辑网格

参考 AlbumsCollectionVC 与 AlbumCollectionCell 的自适应方形封面和清晰标题，删除副标题、字母索引、筛选范围和批量播放入口

专辑详情

参考 AlbumDetailVC 的封面、播放操作与曲目层级，改为 macOS 原生布局，压缩菜单与附加元数据

持续播放入口

参考 macOS 截图和 PopupPlayerVC 的底部常驻思路，只保留当前曲目、进度与基础控制

参考边界

参考信息架构、交互行为和数据请求，不复制 Amperfy 的 GPL 源码、素材或移动端视觉实现

范围控制

本轮优先暂不开发进入条件
专辑、曲目、播放、队列艺术家、歌单、播客、电台核心播放闭环稳定后再讨论
在线流媒体与轻量缓存完整离线下载系统确认缓存策略与磁盘管理后
必要的专辑与曲目信息评分、评论、推荐、社交信息用户明确提出真实需求后

每阶段验收

功能在真实 Navidrome 数据上完成主路径
界面先提交可见界面供确认，再扩展下一阶段
稳定性覆盖加载、空数据、断网、凭据失效和流播放失败
工程保持标准 Xcode 工程，不修改 Scheme，不引入构建脚本
本文件用于确认方向，获准后再开始核心功能实现
